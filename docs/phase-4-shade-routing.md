# Phase 4: 그늘 경로 최적화

직접 높이 기반 기존 계약과 별도로 [공공 3D 모델 기반 예측 API](model-based-shade-prediction.md)를 추가했다. 새 API의 `prediction.modeledShadeRatio`는 이 문서의 `AVAILABLE`/실제 커버리지로 취급하지 않는다.

2026-10-27에 `POST /api/v1/routes/search`의 `mode: "shade"`를 구현했다. **합성 건물·지상 보행 그래프에서 그림자 계산과 최적 경로 선택을 검증한 상태**다. 서울숲 실제 자료의 건물 목록·높이 검증은 끝나지 않았으며 평가 허용 구역은 계속 0곳이다. 실제 자료를 강제로 완전한 목록으로 변경하지 않았다.

이후 [50m 공공 원본 재검증](pilot-field-review-2026-10-27.md)에서 직접 높이 대조와 미검증 소구역 그래프를 준비했다. [공공 지형·3D 추가 대조](public-spatial-pilot-2026-10-27.md)에서는 DEM 16개와 건물 모델을 확보했지만 직접 높이 이전과 지형 모델 승인은 보류했다. 실제 그늘 검색은 계속 보류하며 최신 Python 60개, 기존 JVM 142개 통과 기록이 있다. 아래 139개는 최적화 최초 검증 당시 기록이다.

## 요청과 응답

기존 요청에 `mode: "shade"`를 지정한다. `travelMode`의 기본값은 walking, `mode`의 기본값은 fastest다. 요청 필드는 추가하지 않았으며 우회 한도는 첫 정책에서 고정 30%다. sunlight·가중치·후보 수 설정은 지원하지 않는다.

```json
{
  "origin": {"longitude": 127.0374, "latitude": 37.5445},
  "destination": {"longitude": 127.0430, "latitude": 37.5480},
  "travelMode": "walking",
  "mode": "shade",
  "departureAt": "2026-10-27T12:00:00+09:00"
}
```

위 실제 서울숲 좌표는 현재 낮에 **503 SHADE_DATA_UNAVAILABLE**이다. 성공의 가짜 경로나 그늘 비율을 만들지 않는다. fastest로 요청하면 같은 실제 보행 경로 800.8m / 573초와 INCOMPLETE_COVERAGE, coverage=0, shadeRatio=null을 반환한다.

성공 시 기존 `routes[]`에 요청한 mode의 경로 한 개를 반환한다. `baselineDurationSeconds`는 같은 스냅 지점의 실제 fastest 시간이며 `additionalDurationSeconds`는 각각 올림한 선택 시간과 기준 시간의 차이다. 최상위 dataVersion은 보행 그래프, shadeEvaluation.dataVersion은 건물 버전이다. 좌표·snapping·단위·출처 계약을 유지한다.

최적화 정책 버전은 `shade-v1-min-sun-seconds-detour30-pareto100k-sections12k`, 그림자 모델은 `building-prism-v2-noaa-5179-minsun5-height-source`다.

## 선택 기준

1. 기존 Dijkstra로 fastest를 계산하고 해당 경로의 출발·도착 스냅을 고정한다. 더 그늘진 다른 도로로 출발 위치를 이동시키지 않는다. 건물 평가가 가능해도 지상 보행 맥락을 검증한 그래프 버전 목록에 없으면 503 SHADE_DATA_UNAVAILABLE로 보류한다.
2. 원래 보행 방향·계단 속도와 연결 관계를 유지한다. 출발점에서의 최소 시간과 도착점까지의 최소 시간을 계산해 `fastest 원시 시간 × 1.3` 이내 경로에 참여할 수 있는 구간을 남긴다. 원시 시간의 부동소수점 비교에만 1e-8초 여유를 둔다.
3. 기준 경로와 후보 구간 모두를 **한 SQL 문장의 같은 건물 스냅샷·같은 태양 위치**로 평가한다. 태양 위치의 기준점은 fastest 경로 bbox 중심이며 시각은 evaluatedAt이다. 출발·도착이 도로 중간이면 잘린 구간을 별도로 평가한다. 전체 edge의 그늘 비율을 잘린 구간에 복사하지 않는다.
4. 기준 경로 및 시간 한도 안 후보 구간이 모두 AVAILABLE이어야 한다. 알려지지 않은 구간을 그늘 0으로 채우거나 비교 대상에서 조용히 빼지 않는다. 따라서 가능한 그늘 경로가 일부 있어도 다른 후보의 자료가 부족하면 초기 정책은 요청을 보류한다.
5. 각 구간의 `예상 통과 초 × (1 - 그늘 길이 비율)`을 합친 **햇빛 노출 시간**을 최소화한다. 노출 시간이 같으면 예상 소요 시간이 짧은 경로를 선택한다. 더 높은 그늘 비율만으로 길게 우회하지 않는다.
6. 노출 시간과 소요 시간을 함께 보존하는 Pareto label 탐색을 사용한다. 조금 더 햇빛을 받더라도 빠른 중간 경로를 남겨야 남은 우회 예산을 올바르게 적용할 수 있다. 후보 구간 12,000개, 생성 label 100,000개, label 탐색 약 2초를 한도로 하며 초과 시 미완성 결과를 반환하지 않는다. JDBC 공간 쿼리는 기존 3초 제한을 유지한다. 전체 요청의 하드 실시간 제한이나 부하 검증을 의미하지 않는다.

응답 shadeRatio는 선택한 구간들의 **EPSG:5179 그늘 길이 합 / 전체 길이 합**이다. 예상 통과 시간으로 가중한 비율과 구분한다. 같은 선분을 다시 통과하면 해당 길이를 다시 센다. 그늘이 확인되지 않으면 null이며 확인된 0과 구분한다. 알려진 그늘이 모두 0이거나 노출 시간 이득이 없으면 fastest와 같은 경로가 선택될 수 있고 추가 시간은 실제 차이인 0이다.

## 실패 계약

| HTTP | code | 의미 |
| --- | --- | --- |
| 503 | SHADE_DATA_UNAVAILABLE | 기준 경로/비교 구간의 미확인 목록·높이·경계·자료 없음·공간 계산 실패, 지상 그래프 미검증 또는 일관된 평가 결과를 확보하지 못함 |
| 422 | SHADE_TIME_UNSUPPORTED | 밤, 태양 고도 5도 미만, 2000..2100 밖 |
| 503 | ROUTE_SEARCH_LIMIT_EXCEEDED | 후보 구간/label/탐색 시간 제한 초과 |

기존 INVALID_ROUTE_QUERY, OUTSIDE_SUPPORTED_AREA, ROUTE_NOT_FOUND, ROUTING_DATA_UNAVAILABLE도 유지한다. 오류는 application/json, 최상위 code/requestId와 동일한 X-Request-Id 헤더를 제공한다. fastest는 환경 자료 부족·밤에도 기존 200 응답과 shadeEvaluation 상태를 유지한다.

Flutter는 mode의 `shade` 값과 위 세 코드만 추가로 처리하면 기존 DTO를 사용할 수 있다. 자료 부족 시 기존 fastest 경로를 유지하고 그늘 안내를 표시할 수 있다. 서버는 shade 요청을 fastest 성공으로 자동 치환하지 않는다. fastest의 AVAILABLE도 모든 대안 구간의 평가 가능성을 보장하지 않는다.

## 실제 서울숲 확인 — 2026-10-27

로컬 서버를 새 JAR로 실행하고 Actuator/DB UP을 확인했다. 실제 낮·밤·낮은 태양 고도·지원 연도 밖의 fastest/shade 총 8개 HTTP 요청을 확인했다. 낮 fastest는 기존 800.8m / 573초, 그늘 INCOMPLETE_COVERAGE를 유지하고 shade는 503을 반환한다. 나머지 시각의 fastest는 각각 NIGHT/LOW_SUN/UNSUPPORTED_TIME, shade는 422 SHADE_TIME_UNSUPPORTED다. 오류의 Content-Type과 requestId/헤더 연결도 검사한다.

OpenAPI에서 mode enum이 fastest/shade인 것을 확인했다. 최종 로컬 8개 응답은 약 36~412ms, 추가 warm fastest 3회는 약 37~52ms였다. 일반 경로의 단일 평가 쿼리와 최적화용 배치 쿼리를 나눠 일반 요청에 불필요한 다중 경로 분해를 추가하지 않았다. 실제 자료는 미평가 상태이므로 이 시간은 전체 그림자 최적화나 부하 환경의 성능 근거가 아니다.

활성 보행 그래프는 `osm-v1-83740be9358cef8de74cc4039d9835e9f90883e1dd2ba72ede48459c25968795`, 건물은 `buildings-v1-a620390ad03e64ca19d2657fac3e20924a54260afe92a557cef373282cf56203`다. 건물 14,075개/직접 높이 5,585개, inventoryComplete=false, 최대 높이 상한 null을 유지한다. 요청 전후 건물 상태가 같음을 조회로 확인했다. 최신 실제 요청/응답은 Git에서 제외되는 `data/public-buildings/shade-routing-verification-20261027-final/`에 보관한다.

## 실제 제공 전 남은 조건

[작은 구역 조사](shade-pilot-area-2026-10-26.md)의 건물 형상 불일치와 누락 높이, 주변 미확인 건물의 검증된 상한을 보완해야 한다. **현장 방문·사진·현장 실측은 모델 기반 경로 제공의 필수 조건이 아니다.** 지상 보행 맥락과 지형 적합성도 공식 자료로 검증할 수 있다. 현장 관측은 이후 모델 정확도를 독립적으로 평가하는 수단이며, 공공자료로 계산한 예측과 구분한다. inventoryComplete를 임의로 바꾸지 않는다.

현재 보행 그래프는 bridge/tunnel/indoor/level 등 원본 태그를 보존하지 않아 최적화 시 해당 구간을 자동으로 제외할 수 없다. 건물 목록이 완전하다는 사실만으로 보행로가 지상이라는 근거가 되지 않는다. 따라서 `SHADE_GROUND_VERIFIED_DATASETS` 기본값은 빈 목록이며 현재 실제 그래프를 넣지 않았다. 건물 자료가 완전해져도 별도의 지상 검증 없이는 그늘 경로를 제공하지 않는다.

실서비스에서 허용하기 전에는 검증된 지상 그래프를 따로 준비하거나 도로별 구조 속성을 보존·제외하는 단계가 필요하다. 조사 근거가 있는 **전체 그래프 버전**만 위 환경 변수에 쉼표로 나열한다. Spring 설정은 `igilro.shade-routing.ground-verified-datasets`이며 그래프 버전이 바뀌면 다시 확인해야 한다. 작은 구간만 확인한 사실로 전체 서울숲 그래프를 허용하지 않는다. 합성 그래프만 명시적으로 지상으로 구성했다.

이 목록은 현장 답사 여부가 아니라 해당 그래프에 대한 모델 적용 근거를 의미한다. 공식 보도/도로·교량·터널/입체 구조 자료와 충분한 해상도·갱신 시점의 지형 자료, 공식 항공영상 등의 대조로도 근거를 확보할 수 있다. OSM에 구조 태그가 없다는 사실이나 대략적인 전국 DEM 한 종류만으로 해당 근거를 충족했다고 보지는 않는다.

### 공공데이터만으로 진행하는 순서

1. 비교 경로가 가능한 300m 소구역에서 GIS·HUB의 건물 ID/형상/직접 높이를 대조한다. 누락 높이는 이용 가능한 공식 건물 단위 높이·3D 자료로 보완한다. 직접 높이가 없는 건물을 삭제하거나 층수를 직접 높이로 치환하지 않는다.
2. 공식 건물 목록·영상/3D 자료로 형상 차이와 누락을 검토하고, 그림자 영향 범위의 높이 상한·자료 경계 근거를 확보한다. 자료가 완전하다는 공급자의 조회 결과와 실제 분석 범위의 데이터 적합성을 구분한다.
3. 공식 지형 및 도로 구조 자료로 교량·지하·실내·고가 구간을 제외하고 지면 높이 차이를 평가한다. 평면 모델을 적용할 수 없는 곳은 제외하거나 지형을 반영하는 모델로 확장한다. 수평·수직 좌표계, 단위, 정확도, 해상도와 자료 시각을 확인한다.
4. 원본 파일/ID·체크섬·검토 범위·판정 근거를 기록한다. 새 파생 높이가 필요하면 직접 높이와 구분하고 적격성 정책을 검증한 뒤 사용한다. 근거가 확보된 소구역에만 자료를 적재하고 mode=shade의 실제 성공·추가 시간·시간대별 결과를 확인한다.

[서울시 공식 설명](https://news.seoul.go.kr/gov/archives/528155?listPage=1)은 S-Map의 건축물·지형·교량 등 자료를 안내하고, [오픈랩 데이터셋 가이드](https://openlab.eseoul.go.kr/siteData/guide/guide_dataset.pdf)는 데이터셋 조회·다운로드 절차를 설명한다. 이는 특정 3D/지형 원본을 현재 키로 즉시 내려받아 서버에 사용할 수 있음을 뜻하지 않는다. 자료별 제공 범위·접근 방법·이용 조건을 확인해야 한다. 현재는 필요한 추가 원본을 확보하지 못해 미허용 상태를 유지한다.

공공자료로 검증한 모델의 계산 가능 상태와 현장 정확도 검증 여부는 별도로 기록한다. 기존 AVAILABLE은 입력 자료로 전체 경로를 계산할 수 있다는 상태이며 현장 실측을 보증하는 상태가 아니다.

평평한 지면·수직 건물·출발 시각 고정의 기존 모델 가정을 유지한다. 교량·터널·실내, 나무·지형·구름, 이동 중 태양 변화·실제 보행 시간·온열감은 검증 범위 밖이다. 전체 실제 구역을 사용할 수 있는 상태나 운영 부하 검증 완료를 주장하지 않는다.
